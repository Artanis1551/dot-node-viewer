# Adding a Model to the Test Suite

Follow this workflow whenever adding a concrete neural network model (via a local path, a remote download URL, or a deterministic Python model generator) to the `dot-node-viewer` test suite.

---

## 1. Core Rules for Model Test Fixtures

1. **Never Bloat Git History with Large Binaries**
   - **Small models (256 KB or smaller):** Commit directly into `tests/DotNodeViewer.Core.Tests/Fixtures/<format-folder>/` for fast, offline CI execution.
   - **Large models (greater than 256 KB):** NEVER commit directly to Git. Store the binary in the git-ignored `tests/DotNodeViewer.Core.Tests/.model-cache/<format-folder>/` directory and register its metadata (`sourceUrl`, lowercase `sha256`, `byteLength`) in `tests/DotNodeViewer.Core.Tests/Fixtures/models.manifest.json`.
   - Ensure `.model-cache/` is listed in `tests/DotNodeViewer.Core.Tests/.gitignore`.

2. **Supported Formats & Directory Mapping**
   The core parser library supports six format families:
   | Format Slug (`format`) | Fixture Folder | Manifest ID Prefix | Snapshot Format Display String |
   |---|---|---|---|
   | `onnx` | `Fixtures/onnx` | `onnx-` | `ONNX IR v9` / `ONNX IR v3` |
   | `tflite` | `Fixtures/tflite` | `tflite-` | `TensorFlow Lite v3` |
   | `executorch` | `Fixtures/executorch` | `executorch-` | `ExecuTorch` |
   | `pytorch` | `Fixtures/pytorch` | `pytorch-` | `PyTorch` |
   | `pytorch-pt2` | `Fixtures/pytorch_pt2` | `pytorch_pt2-` | `PyTorch ExportedProgram (.pt2)` |
   | `keras` | `Fixtures/keras` | `keras-` | `Keras (.keras/.h5)` |

   *Note: For `pytorch-pt2`, the canonical format string in `models.manifest.json` is `pytorch-pt2`, but the directory slug and ID prefix use an underscore (`pytorch_pt2` and `pytorch_pt2-`).*

3. **Always Verify Integrity with SHA-256 and Byte Length**
   - Every test model—whether committed in `Fixtures/` or cached in `.model-cache/`—must have its exact `byteLength` and lowercase `sha256` digest recorded in `models.manifest.json`.
   - `ModelFixtureLoader.OpenVerifiedModelStreamAsync` validates both before any parser code runs.

4. **Independent Ground Truth vs. Golden IR Snapshots**
   - **Golden Topology Snapshot (`<stem>.expected.json`):** Golden snapshot of the parsed `ModelGraph` emitted by `DotNodeViewer.Cli snapshot`.
   - **Independent Ground Truth (`<stem>.truth.json`):** Generated by native Python scripts in `tools/model-gen/<format>/` (using `onnx`, `tensorflow`, `torch`, `executorch`, or `keras`).
   - **Golden snapshots must NEVER be blindly regenerated** to make a failing test pass. Always cross-check against independent ground truth (`*.truth.json` for synthetic fixtures, or reference Netron / model architecture docs for real-world models).

5. **Assert Both Graph Topology and Lazy Weight Slicing**
   - Every model test must verify:
     1. **Format detection:** `IModelFormatDetector` identifies the format from the stream header and leaves `stream.Position == 0`.
     2. **Graph metadata & I/O shapes:** Expected subgraph count, total node count, operator histogram, and input/output tensor shapes and data types.
     3. **Zero-allocation weight slices:** At least one initializer/weight tensor has a valid `TensorDataSlice` (`StreamOffset > 0`, `ByteLength > 0`, and `StreamOffset + ByteLength <= fileByteLength`) without allocating weight buffers on the managed heap.

## 2. Step-by-Step Execution Workflow

### Step 1: Stage & Inspect the Model Binary

#### Option A: Real-World Model (Local File or Download URL)
Run the staging script `.agents/skills/add-test-model/scripts/stage-model.sh` to download/copy the binary, compute its SHA-256 digest, inspect magic bytes, and place it in the right tier:

```bash
bash .agents/skills/add-test-model/scripts/stage-model.sh "<file-path-or-url>" "<format-slug>" [test-project-dir] [max-committed-kb] [companion-files...]
```

- `<file-path-or-url>`: Local path (e.g. `~/Downloads/mobilenet_v2_1.0_224_quant.tflite`) or remote URL (e.g. `https://github.com/onnx/models/.../mobilenetv2-7.onnx`).
- `<format-slug>`: One of `onnx`, `tflite`, `executorch`, `pytorch`, `pytorch-pt2` (or `pytorch_pt2`), `keras`.
- `[companion-files...]`: Optional companion files (e.g., external weight `.bin` files for ONNX external data models) to stage in the same directory.

#### Option B: Deterministic Synthetic Model Generator (`tools/model-gen/`)
If adding a minimal synthetic fixture to test a parser feature or edge case:
1. Use the pinned Python virtualenv for the format under `tools/model-gen/<format>/.venv/`:
   - ONNX: `tools/model-gen/onnx/gen_onnx.py`
   - TensorFlow Lite: `tools/model-gen/tf/gen_tflite.py`
   - Keras: `tools/model-gen/tf/gen_keras.py`
   - PyTorch (`.pt`): `tools/model-gen/torch/gen_pytorch.py`
   - PyTorch 2 (`.pt2`): `tools/model-gen/torch/gen_pt2.py`
   - ExecuTorch (`.pte`): `tools/model-gen/torch/gen_executorch.py`
2. The generator outputs both the binary fixture (`<stem>.<ext>`) and the ground-truth snapshot (`<stem>.truth.json`) into `tests/DotNodeViewer.Core.Tests/Fixtures/<format-folder>/`.

---

### Step 2: Register the Model in `models.manifest.json`

Add the model entry to `tests/DotNodeViewer.Core.Tests/Fixtures/models.manifest.json`:

```json
    {
      "id": "tflite-mobilenet_v2_1.0_224_quant",
      "format": "tflite",
      "fileName": "mobilenet_v2_1.0_224_quant.tflite",
      "tier": "cached",
      "relativePath": ".model-cache/tflite/mobilenet_v2_1.0_224_quant.tflite",
      "sourceUrl": "https://raw.githubusercontent.com/google-coral/test_data/master/mobilenet_v2_1.0_224_quant.tflite",
      "sha256": "7aad0c74c5e3c06e5eb3c827e13304fdd68a83da6087d92ee169c24ff9fd4776",
      "byteLength": 3610798,
      "expectedSnapshot": "Fixtures/tflite/mobilenet_v2_1.0_224_quant.expected.json"
    }
```

*Note: For `committed` models or local-only models without a public URL, set `"sourceUrl": null` (do not omit the property).*

See `references/manifest-and-snapshot-schema.md` for complete schema specifications.

---

### Step 3: Extract & Verify the Expected Topology Snapshot

1. Generate the golden topology snapshot via the CLI tool:
   ```bash
   dotnet run --project tools/DotNodeViewer.Cli -c Release --no-build -- snapshot "<path-to-model>" --id "<model-id>" > "tests/DotNodeViewer.Core.Tests/Fixtures/<format-folder>/<stem>.expected.json"
   ```

2. **Cross-check against ground truth:**
   - If a `.truth.json` file exists (synthetic fixture), verify that `nodeCount`, `operatorHistogram`, `inputs`, and `outputs` match.
   - For real-world models, inspect against reference Netron or published model topology.
   - Ensure `sampleWeightSlice` has valid non-zero `streamOffset` and `byteLength`.

---

### Step 4: Wire Up Test Cases

1. **Manifest Regression Coverage (Automatic):**
   `tests/DotNodeViewer.Core.Tests/ModelManifestTests.cs` partitions manifest testing into format-specific parameterized methods:
   - `ParseRegisteredOnnxModel_MatchesExpectedTopology`
   - `ParseRegisteredTfliteModel_MatchesExpectedTopology`
   - `ParseRegisteredExecuTorchModel_MatchesExpectedTopology`
   - `ParseRegisteredPyTorchModel_MatchesExpectedTopology`
   - `ParseRegisteredPyTorchPt2Model_MatchesExpectedTopology`
   - `ParseRegisteredKerasModel_MatchesExpectedTopology`

   Any newly registered entry in `models.manifest.json` matching that format is **automatically discovered and executed** via `[MethodDataSource]`.

2. **Model-Specific Feature Assertions (`Formats/<Format>ModelTests.cs`):**
   When the model is added to test a specific capability (e.g. per-channel quantization, nested control-flow graphs, custom delegate payloads, or external weight references):
   - Add a targeted `[Test]` method in `tests/DotNodeViewer.Core.Tests/Formats/<Format>ModelTests.cs`.
   - If accompanied by `.truth.json`, add the stem to `Committed<Format>Fixtures_CrossCheckAgainstPythonGroundTruth`.

---

### Step 5: Verify via `dotnet test` & Pipeline Inspection

1. **Run Format Manifest & Integration Tests:**
   ```bash
   # Run format manifest snapshot test
   dotnet test --project tests/DotNodeViewer.Core.Tests -c Release --no-restore -- --treenode-filter "/*/*/ModelManifestTests/ParseRegistered<Format>Model*"

   # Run format integration tests
   dotnet test --project tests/DotNodeViewer.Core.Tests -c Release --no-restore -- --treenode-filter "/*/*/<Format>ModelTests/*"
   ```

2. **Run All Format Model Tests Locally (Parity with CI):**
   ```bash
   bash tools/ci/run-model-tests.sh <format>
   ```
   *(Supported formats: `onnx`, `tflite`, `executorch`, `pytorch`, `pytorch-pt2`, `keras`)*

3. **Verify Pipeline Inspection Report:**
   ```bash
   python3 tools/ci/report-tested-models.py <format>
   ```
   Ensures the new model is properly enumerated, sizes and SHA-256 hashes match, and formatted Markdown tables are emitted.
